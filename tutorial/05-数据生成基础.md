# 数据生成基础

数据生成是维护配方、战利品表等 JSON 的另一种开发方式。上一篇的手写文件已经能够工作，初学者可以选择性学习或跳过。

## 一、配置数据生成

数据生成用 Java 构建器写出 JSON。它仍然是开发时运行的一次性任务，不会在玩家合成或打开箱子时临时生成文件。运行流程是：

1. 游戏完成注册，确保构建器可以取得真实的物品、方块和标签查找器。
2. `GatherDataEvent.Client` 触发。
3. 各数据提供器生成 JSON。
4. 任务把文件写入输出目录并结束。

数据提供器是真正定义内容的类。事件只负责在 Data 运行配置中调用这些提供器，所以不要把配方或战利品规则直接写进事件方法。

数据生成的整体流程、客户端与服务器事件以及命令行参数见[资源数据生成](/docs/resources/#data-generation)。

标准工程的 `data` 运行配置已经设置好输出到：

```text
src/generated/resources/
├─ assets/tutorialmod/
└─ data/tutorialmod/
```

`build.gradle` 还会把 `src/generated/resources` 加入主资源目录，所以生成文件会随模组一起构建。生成文件不要手动搬回 `src/main/resources`；应把它们保留在生成目录，并修改提供器后重新生成。

工程的数据运行配置还会把 `src/main/resources` 传给 `--existing` 参数，让提供器可以检查已有资源。因此，迁移手写 JSON 时可以先保留原文件，比较生成结果后再删除重复版本。

本篇涉及以下 Java 文件：

```text
src/main/java/com/example/tutorialmod/
├─ TutorialMod.java              修改：登记数据生成事件
└─ datagen/
   ├─ ModDataGenerators.java     新建：统一入口
   ├─ ModLanguageProvider.java   新建：翻译提供器
   ├─ ModRecipeProvider.java     新建：配方提供器
   ├─ ModBlockLoot.java          新建：方块掉落规则
   └─ ModLootTables.java         新建：战利品表提供器
```

所有 `datagen` 类都放在 `com.example.tutorialmod.datagen` 软件包中。代码片段省略了导入语句，创建类后可以按 `Alt+Enter` 导入。

翻译、配方和战利品表生成可以分别选择。例如只生成配方时，不需要创建 `ModLanguageProvider`、`ModBlockLoot`、`ModLootTables`。无论选择哪一种，都需要创建 `ModDataGenerators` 并在 `TutorialMod` 中登记事件。

在 `com.example.tutorialmod` 下新建 `datagen` 软件包，再创建 `ModDataGenerators`。先加入数据生成入口：

```java
public final class ModDataGenerators {
    public static void gatherData(GatherDataEvent.Client event) {
        // 创建提供器后，在这里逐行登记。
    }
}
```

这个类本身不生成内容。后面每创建一个提供器，就在 `gatherData` 中增加一行 `event.createProvider(...)`。事件调用哪几个提供器，任务就生成哪几类文件。

打开入口类，在构造方法中加入：

```java
modEventBus.addListener(ModDataGenerators::gatherData);
```

这一行连接的是模组事件总线。普通游戏启动也会注册监听器，但只有 Data 运行配置才会触发 `GatherDataEvent.Client`，因此不会在客户端进世界时反复生成文件。

### 1. 生成翻译（可选）

翻译文件只是“翻译键到显示文本”的映射，因此适合作为第一个数据提供器。创建 `ModLanguageProvider`：

```java
public final class ModLanguageProvider extends LanguageProvider {
    private final String locale;

    public ModLanguageProvider(PackOutput output, String locale) {
        super(output, TutorialMod.MODID, locale);
        this.locale = locale;
    }

    @Override
    protected void addTranslations() {
        switch (locale) {
            case "en_us" -> {
                addBlock(ModBlocks.SILVER_ORE, "Silver Ore");
                addItem(ModItems.SILVER_INGOT, "Silver Ingot");
            }
            case "zh_cn" -> {
                addBlock(ModBlocks.SILVER_ORE, "银矿石");
                addItem(ModItems.SILVER_INGOT, "银锭");
            }
            default -> {
            }
        }
    }
}
```

父类构造方法接收输出目录、Mod ID 和语言代码。`addBlock`、`addItem` 会根据对象自动生成正确的翻译键，因此不需要手动拼写 `block.tutorialmod.silver_ore` 和 `item.tutorialmod.silver_ingot`。

在 `ModDataGenerators.gatherData` 中分别登记两个语言：

```java
event.createProvider(output -> new ModLanguageProvider(output, "en_us"));
event.createProvider(output -> new ModLanguageProvider(output, "zh_cn"));
```

运行后会写到：

```text
assets/tutorialmod/lang/en_us.json
assets/tutorialmod/lang/zh_cn.json
```

如果只维护一种语言，可以只登记对应的一行。更多对象类型和自定义翻译键见[翻译数据生成](/docs/resources/client/i18n/#datagen)。

### 2. 生成配方（可选）

在 `ModRecipeProvider.java` 中先创建类骨架和构造方法：

```java
public final class ModRecipeProvider extends RecipeProvider {
    private ModRecipeProvider(HolderLookup.Provider registries, RecipeOutput output) {
        super(registries, output);
    }

    // buildRecipes 和 Runner 会继续加入这个大括号内。
}
```

这个构造方法不会把 Data 任务提供的注册表查询器和输出对象传给父类 `RecipeProvider`。

在类中继续加入决定配方内容的 `buildRecipes`：

```java
@Override
protected void buildRecipes() {
    SimpleCookingRecipeBuilder.smelting(
                    Ingredient.of(ModBlocks.SILVER_ORE.get()), // 输入
                    RecipeCategory.MISC,                       // 配方书分类
                    CookingBookCategory.MISC,                  // 烹饪书分类
                    ModItems.SILVER_INGOT.get(),               // 输出
                    0.1F,                                      // 经验
                    200)                                       // 200 tick
            .unlockedBy("has_silver_ore", has(ModBlocks.SILVER_ORE.get()))
            .save(output, "tutorialmod:silver_ingot_from_smelting_silver_ore");
}
```

这段代码对应上一篇的银矿石熔炼配方 JSON。`.unlockedBy` 使用“获得银矿石”作为配方书解锁条件；`.save` 的第二个参数是带命名空间的配方 ID。

`RecipeProvider` 本身不是数据提供器，因此在 `ModRecipeProvider` 的大括号内继续加入静态嵌套类 `Runner`：

```java
public static final class Runner extends RecipeProvider.Runner {
    public Runner(PackOutput output, CompletableFuture<HolderLookup.Provider> lookupProvider) {
        super(output, lookupProvider);
    }

    @Override
    protected RecipeProvider createRecipeProvider(
            HolderLookup.Provider lookupProvider, RecipeOutput output) {
        return new ModRecipeProvider(lookupProvider, output);
    }

    @Override
    public String getName() {
        return "Tutorial Mod Recipes";
    }
}
```

`Runner` 位于 `ModRecipeProvider.java` 中`。它负责把 `ModRecipeProvider` 交给数据生成任务运行；`Runner` 和 `getName` 都是必需部分。

在 `ModDataGenerators.gatherData` 中加入：

```java
event.createProvider(ModRecipeProvider.Runner::new);
```

`Runner::new` 是构造方法引用，`createProvider` 会在生成任务需要运行配方提供器时调用它。成功生成后，文件位于：

```text
src/generated/resources/data/tutorialmod/recipe/
    silver_ingot_from_smelting_silver_ore.json
```

`RecipeProvider` 还会用 `.unlockedBy` 自动生成配方书所需的解锁进度。新增其他配方时，通常在 `buildRecipes` 中继续调用相应构建器即可。

有序、无序、切石和锻造等配方的数据生成方法见[配方数据生成](/docs/resources/server/recipes/#data-generation)。

### 3. 生成方块战利品表（可选）

在 `ModBlockLoot.java` 中先创建类骨架和构造方法：

```java
public final class ModBlockLoot extends BlockLootSubProvider {
    public ModBlockLoot(HolderLookup.Provider registries) {
        super(Set.of(), FeatureFlags.REGISTRY.allFlags(), registries);
    }

    // generate 和 getKnownBlocks 会继续加入这个大括号内。
}
```

构造方法与配方提供器类似，只负责把生成所需的参数交给父类。`Set.of()` 表示没有额外设置爆炸抗性物品，`FeatureFlags.REGISTRY.allFlags()` 让本次生成考虑全部已启用功能。

在类中继续加入 `generate`，写出掉落规则：

```java
@Override
protected void generate() {
    dropSelf(ModBlocks.SILVER_ORE.get());
}
```

`dropSelf` 会生成“掉落自身”的战利品池，并附带通常需要的爆炸掉落处理。对应的手写 JSON 位于上一篇的 `loot_table/blocks/silver_ore.json`。

继续在类中加入 `getKnownBlocks`，告诉生成器本次检查哪些方块：

```java
@Override
protected Iterable<Block> getKnownBlocks() {
    return List.of(ModBlocks.SILVER_ORE.get());
}
```

如果只生成掉落规则却漏掉 `getKnownBlocks`，生成器会检查当前模组的全部方块，其他没有规则的文件就会报错。以后添加普通方块时，需要在这里加入它并选择 `dropSelf` 或其他规则。

`ModBlockLoot` 是战利品表的子提供器，还需要用 `LootTableProvider` 把它接到数据生成任务。创建独立的 `ModLootTables` 类：

```java
public final class ModLootTables extends LootTableProvider {
    public ModLootTables(
            PackOutput output,
            CompletableFuture<HolderLookup.Provider> lookupProvider) {
        super(
                output,
                Set.of(),
                List.of(new LootTableProvider.SubProviderEntry(
                        ModBlockLoot::new,
                        LootContextParamSets.BLOCK)),
                lookupProvider);
    }
}
```

四个父类参数分别表示：输出目录、必须存在的战利品表集合、子提供器及其上下文类型、注册表查询器。这里不需要预先声明必须存在的表，所以第二个参数使用空集合。

精准采集、时运、实体掉落和更多辅助方法见[战利品表数据生成](/docs/resources/server/loottables/#datagen)。

在 `ModDataGenerators.gatherData` 中再加入：

```java
event.createProvider(ModLootTables::new);
```

运行后，方块战利品表会写到：

```text
src/generated/resources/data/tutorialmod/loot_table/blocks/silver_ore.json
```

### 4. 其他可生成内容（可选）

标签和模型也能通过 `BlockTagsProvider`、`ModelProvider` 等提供器生成。它们与配方提供器的思路相同：创建对应子类，在固定方法中加入规则，再登记到 `gatherData`。

本文不要求一次迁移全部 JSON。第 2、3 篇已经写好的模型和标签可以继续放在 `src/main/resources`；需要把它们也纳入数据生成时，再分别添加提供器。完整写法见[标签数据生成](/docs/resources/server/tags/#data-generation)和[模型数据生成](/docs/resources/client/models/datagen/)。

在 IDEA 的 Gradle 面板运行 `runData`，或运行生成的 `Data` 配置。首次运行时可能先编译并加载注册内容，完成后任务会自行退出。生成目录中的文件会逐个创建或更新。

使用这些提供器后，只删除翻译、配方和战利品表中已被生成文件替代的手写版本。未迁移的模型和标签仍由 `src/main/resources` 提供，不要误删。

## 二、重新生成与重载

数据生成、数据重载和资源重载解决的是不同问题：

| 操作 | 作用 |
| --- | --- |
| 运行 `runData` | 执行 Java 提供器，重新写出 JSON |
| `/reload` | 重新加载当前已存在的数据包数据，如配方、战利品表和标签 |
| `F3+T` | 重新加载客户端资源包资源，如模型、贴图和语言 |

修改 `ModRecipeProvider` 等 Java 代码后，必须重新运行 `runData`。`/reload` 不会执行构建器，也不会根据 Java 代码重新计算文件。

已经在运行的数据包发生外部改动时，可以用 `/reload` 重新读取。客户端显示资源发生变化时使用 `F3+T`。模组 JAR 内部资源更新后，通常还需要重新构建并重新启动对应的游戏进程。
