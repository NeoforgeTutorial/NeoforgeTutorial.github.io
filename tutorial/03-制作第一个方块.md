# 制作第一个方块

## 一、方块、方块状态与方块物品

以银矿石为例。方块和物品并不是同一种注册对象：

| 对象 | 含义 |
| --- | --- |
| `Block` | 方块类型。同一种方块只创建一次，世界中的许多位置共同引用它 |
| `BlockState` | 方块在某个位置上的具体状态。没有附加属性时，它也只有默认状态 |
| `BlockItem` | 物品栏中的方块物品。右键使用时，它尝试把方块放入世界 |
| `ItemStack` | 带有数量、数据组件等信息的物品堆。例如 64 个银矿石 |

银矿石是普通完整立方体，有六个表面。世界中的某个位置不会直接保存一个 `Block` 实例，而是保存类似“这里是银矿石的默认方块状态”的引用。方块类负责共同行为，具体位置则通过方块状态参与放置、破坏和渲染。

银矿石没有朝向、开关等变体，因此只会注册一个方块，并拥有一个不带属性的默认状态。

## 二、注册方块

在 `com.example.tutorialmod` 中新建名为 `block` 的软件包，再创建类 `ModBlocks`。

先加入方块专用注册器：

```java
public static final DeferredRegister.Blocks BLOCKS =
            DeferredRegister.createBlocks(TutorialMod.MODID);
```

`DeferredRegister.Blocks` 和上一篇的 `DeferredRegister.Items` 思路相同：先登记准备注册的内容，等 NeoForge 开放注册阶段后再创建它们。它的注册方法会返回 `DeferredBlock`，其中保留具体方块类型的信息。

在 `BLOCKS` 下加入方块，以银矿石为例：

```java
public static final DeferredBlock<Block> SILVER_ORE = BLOCKS.register(
        "silver_ore",
        registryName -> new Block(BlockBehaviour.Properties.of()
                .setId(ResourceKey.create(Registries.BLOCK, registryName))
                .destroyTime(3.0F)
                .explosionResistance(3.0F)
                .requiresCorrectToolForDrops()
                .sound(SoundType.STONE)));
```

`BLOCKS.register` 的第一个参数是注册路径。NeoForge 会把它补全为 `tutorialmod:silver_ore`，并通过 `registryName` 传给创建方块的函数。

方块属性必须包含自身的注册键。`ResourceKey.create(Registries.BLOCK, registryName)` 根据 `registryName` 创建方块注册键，再通过 `.setId(...)` 写入属性。

这些属性各自控制不同的事情：

| 属性 | 作用 |
| --- | --- |
| `destroyTime` | 决定破坏方块所需的时间。石头为 1.5，泥土为 0.5，黑曜石为 50，基岩为 -1（不可破坏） |
| `explosionResistance` | 决定方块的爆炸抗性。石头为 6.0，泥土为 0.5，黑曜石为 1,200，基岩为 3,600,000 |
| `requiresCorrectToolForDrops` | 要求使用正确工具才能产生掉落；未调用时，空手或工具不合格也可能正常掉落 |
| `sound` | 设置方块被击打、破坏或放置时的声音。默认值为 `SoundType.STONE`，更多信息见[声音页面](/docs/resources/client/sounds/) |
| `lightLevel` | 设置方块的发光等级，接收一个带 `BlockState` 参数、返回 0 到 15 的函数。例如，荧石使用 `state -> 15`，火把使用 `state -> 14` |
| `friction` | 设置方块摩擦系数（滑动程度）。默认为 0.6，冰使用 0.98 |

后面的标签会指定“镐”和“铁质等级”，与 `requiresCorrectToolForDrops` 配合决定哪些工具算合格。

最后加入注册入口：

```java
public static void register(IEventBus modEventBus) {
    BLOCKS.register(modEventBus);
}
```

方块注册也可以使用 `registerBlock`，把方块工厂和属性分开传入。它会在内部对属性调用 `setId`，省去.setId(ResourceKey.create(Registries.BLOCK, registryName))：

```java
public static final DeferredBlock<Block> SILVER_ORE = BLOCKS.registerBlock(
        "silver_ore",
        Block::new,
        () -> BlockBehaviour.Properties.of() //后面接要使用的属性
);
```

第三个参数也可以写成 `props -> props` 形式的属性操作函数，在默认属性基础上继续配置。注册自定义方块子类时，同样要把子类构造函数传给第二个参数。

## 三、注册方块物品

现在世界里已经有银矿石方块，但物品栏里还没有能放置它的事物。需要单独注册一个 `BlockItem`。

加入方块物品专用注册器：

```java
public static final DeferredRegister.Items BLOCK_ITEMS =
        DeferredRegister.createItems(TutorialMod.MODID);
```

然后在 `SILVER_ORE` 下方加入：

```java
public static final DeferredItem<BlockItem> SILVER_ORE_ITEM =
        BLOCK_ITEMS.registerSimpleBlockItem(SILVER_ORE);
```

方块和方块物品可以拥有相同的 ID `tutorialmod:silver_ore`，因为它们分别位于方块注册表和物品注册表。代码中使用不同字段区分二者：

- `ModBlocks.SILVER_ORE` 表示世界中的方块类型。
- `ModBlocks.SILVER_ORE_ITEM` 表示物品栏中的方块物品。

这里把 `DeferredBlock` 直接交给 `registerSimpleBlockItem`。`registerSimpleBlockItem` 还会把名称翻译键设为 `block.tutorialmod.silver_ore`，使方块物品和方块共用同一个显示名称。

接着把方块物品加入创造模式标签页。在前面的 `register` 方法中加入：

```java
BLOCK_ITEMS.register(modEventBus);
modEventBus.addListener(ModBlocks::addCreative);

private static void addCreative(BuildCreativeModeTabContentsEvent event) {
    if (event.getTabKey() == CreativeModeTabs.NATURAL_BLOCKS) {
        event.accept(SILVER_ORE_ITEM.get());
    }
}
```

这里使用的是“自然方块”标签页。事件触发时注册已经完成，因此可以安全调用 `get()` 取得真正的 `BlockItem`。

最后在入口类中导入，并在构造方法中调用 `ModBlocks.register(modEventBus)`。入口类的调用方式与上一篇相同。

## 四、补齐方块状态、模型、贴图和名称

方块已经能参与游戏逻辑，但还没有外观。方块资源位于工程的 `src/main/resources/assets/tutorialmod`，先准备这些文件：

```text
assets/tutorialmod/
├─ blockstates/
│  └─ silver_ore.json
├─ items/
│  └─ silver_ore.json
├─ models/block/
│  └─ silver_ore.json
├─ textures/block/
│  └─ silver_ore.png
└─ lang/
   ├─ en_us.json
   └─ zh_cn.json
```

方块状态文件位于 `src/main/resources/assets/tutorialmod/blockstates/silver_ore.json`。银矿石没有自定义状态属性，所以文件中的 `variants` 只有一个空字符串键：

```json
{
  "variants": {
    "": {
      "model": "tutorialmod:block/silver_ore"
    }
  }
}
```

`variants` 根据方块状态选择模型。空字符串 `""` 表示不附加任何状态条件，因此银矿石唯一的默认状态会使用 `tutorialmod:block/silver_ore` 模型。文件名必须与注册名 `silver_ore` 一致。

方块模型位于 `src/main/resources/assets/tutorialmod/models/block/silver_ore.json`，并使用原版的 `cube_all` 父模型：

```json
{
  "parent": "minecraft:block/cube_all",
  "textures": {
    "all": "tutorialmod:block/silver_ore"
  }
}
```

`parent` 让这个模型继承 `cube_all` 的完整立方体结构，`textures.all` 指定六个面共同使用的贴图。`tutorialmod:block/silver_ore` 对应 `assets/tutorialmod/textures/block/silver_ore.png`。原版其他矿石也采用这个结构。

准备一张 16×16 的 `silver_ore.png`，放到 `textures/block`。六个面会复用同一张图，因此不需要制作六张独立贴图。

方块物品的客户端定义位于 `src/main/resources/assets/tutorialmod/items/silver_ore.json`：

```json
{
  "model": {
    "type": "minecraft:model",
    "model": "tutorialmod:block/silver_ore"
  }
}
```

`model.type` 指定使用普通的客户端模型，`model.model` 指向前面创建的方块模型。方块物品直接复用这个模型，因此不需要再创建 `models/item/silver_ore.json`。物品栏会按照定义中的朝向渲染立方体。

最后在 `lang/en_us.json` 和 `lang/zh_cn.json` 中为 `block.tutorialmod.silver_ore` 添加翻译。语言文件的添加方式与上一篇相同；`BlockItem` 使用 `block.` 开头的翻译键，不需要再写一遍 `item.` 开头的名称。

## 五、设置挖掘条件

方块标签需要扩充 Minecraft 已有的标签。先准备这些文件：

```text
data/
└─ minecraft/tags/block/
   ├─ mineable/pickaxe.json
   └─ needs_iron_tool.json
```

这两个标签位于 `minecraft` 命名空间，因为它们扩充了原版标签；标签内部的银矿石 ID 仍是 `tutorialmod:silver_ore`。

先在 `data/minecraft/tags/block/mineable/pickaxe.json` 中让银矿石属于可被镐开采的方块：

```json
{
  "values": [
    "tutorialmod:silver_ore"
  ]
}
```

然后在 `data/minecraft/tags/block/needs_iron_tool.json` 中指定铁质工具等级：

```json
{
  "values": [
    "tutorialmod:silver_ore"
  ]
}
```

第一个标签让镐获得正常挖掘速度；第二个标签表示至少需要铁镐，使木镐或石镐不满足掉落条件。若希望石镐就能满足条件，应改用 `minecraft:needs_stone_tool`。

代码中的 `requiresCorrectToolForDrops()` 和这两个标签承担不同职责：前者关闭“工具不合格也能掉落”的通道，标签则告诉原版哪些工具算合格。缺少对应标签时，方块即使能用正确工具破坏，也可能不会掉落。

完成这些标签后，银矿石已经能用镐正常破坏，但使用合格工具也不会产生物品掉落，因为还没有指定掉落内容的战利品表。战利品表的结构和数据生成会在下一篇处理。
