# 国际化与本地化

I18n（internationalization，国际化）是让程序支持多种语言的设计方式。L10n（localization，本地化）是把文本翻译为用户语言的过程。Minecraft 使用 `Component` 实现这些功能。

## `Component` {#components}

`Component` 是带元数据的一段文本，元数据可包含文本格式等信息。可以通过以下方式创建（以下均为 `Component` 接口中的静态方法）：

| 方法           | 说明                                                                                  |
|----------------|---------------------------------------------------------------------------------------|
| `empty`        | 创建空组件。                                                                          |
| `literal`      | 创建包含给定文本的组件，直接显示该文本而不翻译。                                      |
| `nullToEmpty`  | 给定 null 时创建空组件，否则创建字面量组件。                                          |
| `translatable` | 创建可翻译组件。传入的字符串随后会作为翻译键解析（见下文）。                          |
| `keybind`      | 创建包含给定按键绑定（已翻译）显示名称的组件。                                        |
| `nbt`          | 创建表示给定路径处 [NBT][nbt] 的组件。                                                |
| `score`        | 创建包含计分板目标值的组件。                                                          |
| `selector`     | 创建包含给定[实体选择器][selector]所匹配[实体]名称列表的组件。                        |
| `object`       | 创建包含任意字体对象的组件，例如图集精灵。                                            |

`Component.translatable()` 还有一个可变参数，用于接收字符串插值元素。它类似 Java 的 `String#format`，但始终使用 `%s`，而不是 `%i`、`%d`、`%f` 等格式说明符；需要时会对对象调用 `#toString()`。

每个 `Component` 都可以通过 `#getString()` 解析。解析通常是惰性的：服务端可以指定 `Component` 并发送给客户端，由各客户端自行解析（不同语言可能得到不同文本）。Minecraft 中许多位置也直接接受 `Component` 并替你完成解析。

:::caution
绝不要让服务端解析 `Component`。应始终把 `Component` 发送给客户端，并在客户端解析。
:::

### `MutableComponent`

所有构造出的组件通常都是 `MutableComponent`。`MutableComponent` 提供添加新组件子节点的方法，这些子节点会追加到当前组件末尾，还提供设置文本[样式]的方法。构造或修改组件时，应始终使用 `MutableComponent`。

### 文本格式

`Component` 可以使用 `Style` 设置格式。`Style` 不可变，修改时会创建新的 `Style` 对象，因此可以创建一次后按需复用。

:::note
只能通过 `MutableComponent` 上的方法设置样式，因此要确认 `Component` 是 `MutableComponent`。
:::

通常可以把 `Style.EMPTY` 作为基础。多个 `Style` 可通过 `Style#applyTo(Style other)` 合并，返回的新 `Style` 优先采用调用 `applyTo()` 的 `Style` 中的设置；如果某项设置缺失，则使用参数中 `Style` 的设置。然后可以这样把样式应用到组件：

```java
MutableComponent text = Component.literal("Hello World!");

// 创建新样式。
Style blue = Style.EMPTY.withColor(0x0000FF);
Style greenShadow = Style.EMPTY.withShadowColor(0xFF00FF00);
// 样式采用类似构建器的模式。
Style blueItalic = Style.EMPTY.withColor(0x0000FF).withItalic(true);
// 除斜体外，也可以设置粗体、下划线、删除线或乱码。
Style bold          = Style.EMPTY.withBold(true);
Style underlined    = Style.EMPTY.withUnderlined(true);
Style strikethrough = Style.EMPTY.withStrikethrough(true);
Style obfuscated    = Style.EMPTY.withObfuscated(true);
// 合并多个样式！
Style merged = blueItalic.applyTo(bold).applyTo(strikethrough);

// 为组件设置样式。
text.setStyle(merged);
// 合并一个新样式。
text.withStyle(Style.EMPTY.withColor(0xFF0000));
```

另一种更复杂的格式控制方式是使用点击和悬停事件：

```java
// 点击事件共有 8 种选项，悬停事件共有 3 种选项。
ClickEvent clickEvent;
HoverEvent hoverEvent;

// 点击时用默认浏览器打开给定 URL。
clickEvent = new ClickEvent.OpenUrl(URI.create("http://example.com/"));
// 点击时打开给定文件。出于安全原因，不能从服务端发送。
clickEvent = new ClickEvent.OpenFile("C:/example.txt");
// 点击时执行给定命令。
clickEvent = new ClickEvent.RunCommand("/gamemode creative");
// 点击时在聊天框中建议给定命令。
clickEvent = new ClickEvent.SuggestCommand("/gamemode creative");
// 点击时改变书页。只适用于书屏幕上下文。
clickEvent = new ClickEvent.ChangePage("1");
// 把给定文本复制到剪贴板。
clickEvent = new ClickEvent.CopyToClipboard("Hello World!");
// 打开对话框屏幕（假设有某个 Holder<Dialog> dialog）
clickEvent = new ClickEvent.ShowDialog(dialog);
// 向服务端发送 identifier 和 payload（默认会记录发送的操作和 payload）
clickEvent = new ClickEvent.Custom(Identifier.fromNamespaceAndPath("examplemod", "custom"), Optional.empty());

// 悬停时显示给定组件。也可以设置格式。
// 注意，悬停提示框中的点击或悬停事件不会生效。
hoverEvent = new HoverEvent.ShowText(Component.literal("Hello World!"));
// 悬停时显示给定物品堆栈模板的完整提示框。
hoverEvent = new HoverEvent.ShowItem(new ItemStackTemplate(...));
// 悬停时显示给定实体的完整提示框。
// 参见 EntityTooltipInfo 可用的构造方法。
hoverEvent = new HoverEvent.ShowEntity(new HoverEvent.EntityTooltipInfo(...));

// 把事件应用到样式。
Style clickable = Style.EMPTY.withClickEvent(clickEvent);
Style hoverable = Style.EMPTY.withHoverEvent(hoverEvent);
```

组件使用的字体也可以设置：

```java
// 设置样式使用的字体。
// 必须匹配可用的 FontDescription.Resource（位于 `assets/<namespace>/font/<path>.json`）

// 指向 `assets/minecraft/font/illageralt.json`
Identifier fontLocation = Identifier.withDefaultNamespace("illageralt");

// 把字体应用到样式
Style customFont = Style.EMPTY.withFont(new FontDescription.Resource(fontLocation));
```

:::warning
在样式里使用 `FontDescription.Resource` 之外的字体描述类型会抛出异常。要使用其他或自定义 `FontDescription`，需创建 `ObjectInfo` 并将其提供给带 `ObjectContents` 的组件。
:::

## 语言文件 {#language-files}

语言文件是 JSON 文件，保存翻译键（见下文）到实际名称的映射，位于 `assets/<modid>/lang/language_name.json`。例如，ID 为 `examplemod` 的模组，其美式英语翻译位于 `assets/examplemod/lang/en_us.json`。Minecraft 支持的语言完整列表见[此处][mcwikilang]。

语言文件通常如下：

```json
{
    "translation.key.1": "Translation 1",
    "translation.key.2": "Translation 2"
}
```

### 翻译键

翻译键是翻译文件中的键。很多情况下，它们遵循 `registry.modid.name` 格式。例如，ID 为 `examplemod`、提供名为 `example_block` 方块的模组，通常要为 `block.examplemod.example_block` 提供翻译。不过，翻译键实际上可以是任意字符串。

如果所选语言中没有某个翻译键的翻译，游戏会回退到美式英语（`en_us`，前提是当前语言不是美式英语）。如果美式英语也没有对应翻译，翻译会静默失败，直接显示原始翻译键。

Minecraft 的一些位置提供获取翻译键的辅助方法。例如，方块和物品都提供 `#getDescriptionId`。对于物品，不仅可以查询，还可以通过 `Item.Properties#overrideDescription` 修改。如果物品名称随底层[数据组件][datacomponent]变化，可以在 `ItemStack` 上设置包含所需可翻译组件的 `CUSTOM_NAME` 数据组件来覆盖。`Item#getName` 还有一个接收 [`ItemStack`][itemstack] 的重载，用于设置物品的默认组件。另一方面，`BlockItem` 通过调用 `Item.Properties#useBlockDescriptionPrefix` 设置描述 ID。`Identifier` 也提供 `toLanguageKey`，接收段或注册表以及可选后缀，用来构造翻译键。

:::tip
翻译键的唯一用途是本地化，不要用它实现游戏逻辑；游戏逻辑应使用[注册名][regname]。
:::

### 翻译模组元数据

翻译文件可通过以下键覆盖[模组信息][modstoml]的部分内容（把 `modid` 替换为实际模组 ID）：

|              | 翻译键                                 | 覆盖内容                                                                     |
|--------------|----------------------------------------|------------------------------------------------------------------------------|
| 描述         | `fml.menu.mods.info.description.modid` | 也可以在 `[[mods]]` 段中放置名为 `description` 的字段。                      |

### 数据生成 {#datagen}

语言文件可以[数据生成][datagen]。继承 `LanguageProvider`，并在 `addTranslations()` 方法中添加翻译：

```java
public class MyLanguageProvider extends LanguageProvider {

    public MyLanguageProvider(PackOutput output) {
        super(
            // 由 `GatherDataEvent.Client` 提供。
            output,
            // 你的模组 ID。
            "examplemod",
            // 要使用的区域设置。可以为不同语言使用多个语言 provider。
            "en_us"
        );
    }
    
    @Override
    protected void addTranslations() {
        // 添加具有给定键和值的翻译。
        this.add("translation.key.1", "Translation 1");
        
        // 为多种常见对象类型提供了辅助方法。多数辅助方法有两个变体：接收对象本身的 add()，
        // 以及接收对象 supplier 的 addTypeHere()。由于泛型类型擦除，supplier 变体需要不同名称。
        // 以下示例都假设所需值已作为对应类型的 supplier 存在。

        // 添加方块翻译。
        this.add(MyBlocks.EXAMPLE_BLOCK.get(), "Example Block");
        this.addBlock(MyBlocks.EXAMPLE_BLOCK, "Example Block");
        // 添加物品翻译。
        this.add(MyItems.EXAMPLE_ITEM.get(), "Example Item");
        this.addItem(MyItems.EXAMPLE_ITEM, "Example Item");
        // 添加物品堆栈翻译。主要用于名称依赖 NBT 的物品。
        this.add(MyItems.EXAMPLE_ITEM_STACK.get(), "Example Item");
        this.addItemStack(MyItems.EXAMPLE_ITEM_STACK, "Example Item");
        // 添加实体类型翻译。
        this.add(MyEntityTypes.EXAMPLE_ENTITY_TYPE.get(), "Example Entity");
        this.addEntityType(MyEntityTypes.EXAMPLE_ENTITY_TYPE, "Example Entity");
        // 添加生物效果翻译。
        this.add(MyMobEffects.EXAMPLE_MOB_EFFECT.get(), "Example Effect");
        this.addEffect(MyMobEffects.EXAMPLE_MOB_EFFECT, "Example Effect");
        // 添加标签键翻译。
        this.add(MyTags.EXAMPLE_TAG, "Example Tag");
        // 添加维度翻译。
        this.addDimension(MyDimensions.EXAMPLE_DIMENSION_KEY, "Example Dimension");
        // 添加生物群系翻译。
        this.addBiome(MyBiomes.EXAMPLE_BIOME_KEY, "Example Biome");
    }
}
```

随后像其他 provider 一样，把它注册到 `GatherDataEvent.Client`。

```java
@SubscribeEvent // 在模组事件总线上
public static void onGatherData(GatherDataEvent.Client event) {
    // 如果添加数据包对象，先调用 event.createDatapackRegistryObjects(...)

    event.createProvider(MyLanguageProvider::new);
}
```
